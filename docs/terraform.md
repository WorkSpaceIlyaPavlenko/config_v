# Развёртывание VPN-узла

`infra/node` — Terraform-модуль одного VPN-узла. Он создаёт сеть, контейнеры Xray и Caddy, образ Caddy и постоянные тома Caddy на уже выбранном Docker daemon. VPS, DNS и установка среды исполнения пока не входят в модуль.

Провайдер настраивается в корневой конфигурации, которую генерирует CLI проекта. Для локальной среды используется отдельный сокет Colima `~/.colima/config-v/docker.sock`. Переменные окружения `DOCKER_CONTEXT` и `DOCKER_HOST` не должны переопределять выбранный узел. SSH-подключение к удалённому daemon требует заранее проверенного ключа сервера. Не открывайте Docker API в интернет.

## Контракт модуля

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `node_name` | `local` | Имя узла и префикс ресурсов |
| `image_platform` | Обязательна | `linux/amd64` или `linux/arm64` выбранного daemon |
| `bind_address` | `127.0.0.1` | Адрес публикации портов |
| `vpn_port` | `8443` | Внешний TCP-порт Xray |
| `http_port` | `8080` | Внешний TCP-порт Caddy HTTP |
| `config_revision` | `initial` | Публичная метка версии конфигурации; изменение пересоздаёт контейнеры |
| `xray_image` | `26.3.27` с SHA256 | Образ Xray, закреплённый по digest |
| `caddy_base_image` | `caddy:2.11.4-alpine` | Основа локально собираемого образа Caddy |
| `xray_memory_mb` / `caddy_memory_mb` | `256` / `128` | Лимиты памяти в MiB |
| `xray_cpus` / `caddy_cpus` | `1` / `0.5` | Максимум процессорных ядер |

Для публичного узла оператор явно выбирает `bind_address = "0.0.0.0"`, `vpn_port = 443`, `http_port = 80`. В контейнерах сохраняются непривилегированные порты: Xray слушает `8443`, Caddy — `8080` и `8443`. REALITY направляет обычное TLS-соединение к `caddy:8443` внутри отдельной сети. TLS-порт Caddy, административный API и метрики наружу не публикуются.

Корневой модуль должен объявить `kreuzwerker/docker` версии `4.6.0` и передать провайдер дочернему модулю. Разделение корней по `runtime/<node>/terraform` даёт каждому узлу собственный state. Не помещайте основной и резервный узлы в один state: недоступность одного daemon не должна мешать обслуживанию второго.

## Конфигурация и ключи

До `terraform plan/apply` CLI проверяет отдельные, уже заполненные тома:

- `config-v-<node>-xray-config` содержит `xray.json`;
- `config-v-<node>-caddy-config` содержит `Caddyfile`.

Оба монтируются только для чтения в `/etc/config-v`; Caddy не получает том с ключом REALITY и UUID пользователей. Содержимое передаётся подготовительным контейнерам через stdin и не попадает в Terraform `env`, `upload`, аргументы провайдера или state. Провайдер Docker не предоставляет источник данных `docker_volume`: модуль ссылается на имена томов, поэтому проверка CLI обязательна. Прямой запуск модуля с отсутствующими томами может создать пустые тома и неработающие контейнеры.

Изменение файла в томе само по себе не означает перечитывание конфигурации процессом. После подготовки новой конфигурации CLI меняет `config_revision`, а Terraform пересоздаёт контейнеры. Для одного узла это прерывает текущие соединения. Автоматическое бесшовное переключение клиентских сессий этим не обеспечивается.

Тома `config-v-<node>-caddy-data` и `config-v-<node>-caddy-runtime` принадлежат Terraform и защищены `prevent_destroy`. При первом запуске Docker копирует в них подготовленные в образе каталоги владельца `65532`. Сохранение существующих томов необходимо для сертификатов и локального центра сертификации. Защита Terraform не предотвращает ручное удаление Docker-тома или потерю VPS; резервные копии нужны на другой машине.

## Изоляция и восстановление

Оба процесса запускаются под UID/GID `65532`, без Linux capabilities, с `no-new-privileges` и корневой файловой системой только для чтения. Контейнеры не получают каталоги Mac, Docker socket или host networking. У производного образа Caddy удалена capability из самого бинарного файла, поэтому он может запускаться с `cap_drop = ALL` и высокими портами. Сборочный контекст содержит только Dockerfile, без конфигураций и ключей.

Эти ограничения дополняют изоляцию виртуальной машины Colima. Они не превращают контейнеры в отдельные виртуальные машины. Среду исполнения VPS нужно выбрать и проверить отдельно до удалённого развёртывания.

`unless-stopped` восстанавливает завершившийся процесс. Terraform не является монитором, а успешный `apply` не подтверждает доступность VPN из России. После запуска проверяются обычный HTTPS и реальный HTTPS-запрос через VLESS-туннель. Основной и резервный VPS должны быть независимыми точками входа; последовательная цепочка из двух серверов не даёт отказоустойчивости.

Обновления образов выполняются явно после проверки. Xray закреплён на стабильном релизе `26.3.27`; более новые prerelease автоматически не выбираются. Caddy закреплён полным тегом `2.11.4-alpine`, но тег не гарантирует неизменность содержимого реестра: для побитового воспроизведения укажите проверенный SHA256 digest в `caddy_base_image`.
